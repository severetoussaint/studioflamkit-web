# 1B2.5.6 — Motor global de precios y catálogo de servicios

## 1. Objetivo

Studio FLAMKIT necesita un motor global que transforme la configuración de una producción en una recomendación de tiempo y precio para nuevas propuestas.

El motor NO sustituye la decisión comercial del Admin.

El motor recomienda.

El Admin puede ajustar el precio final antes de enviar la propuesta.

## 2. Fuente base de precio

La referencia actual de Studio FLAMKIT es:

- 400 USD por hora de audio terminado (PFH).
- 155 palabras por minuto para estimar duración.
- 30 USD como precio base mínimo.

Estos valores pasan a ser configuración global editable desde Admin.

La intención es respetar la lógica comercial existente y evolucionarla hacia un sistema premium accesible, evitando incrementos descontrolados por acumulación de servicios.

## 3. Configuración global

`pricing_settings` contiene reglas globales:

- `base_pfh_rate_usd`
- `words_per_minute`
- `minimum_base_price_usd`
- `base_work_hours_per_audio_hour`
- `max_total_price_multiplier`
- `complexity_multipliers`
- `recommended_adjustment_bounds`
- versión del modelo de precios
- versión del catálogo de servicios

Los valores actuales iniciales son configurables y no deben tratarse como una tarifa contractual permanente.

## 4. Catálogo global de servicios

`pricing_services` contiene servicios reutilizables por futuras propuestas.

Cada servicio define:

- código estable;
- categoría;
- nombre;
- descripción;
- modelo de precio;
- valor del precio;
- tiempo estimado;
- unidad;
- cantidad mínima/máxima;
- cantidad por defecto;
- si está incluido por defecto;
- si está activo;
- si es visible al autor;
- orden de presentación;
- dependencias;
- metadatos.

Cambiar una tarifa en el catálogo afecta a nuevas propuestas.

No modifica propuestas ya aceptadas.

El catálogo es ampliable y editable.

## 6. Modelos de precio

El motor admite:

- `included`
- `percent_of_base`
- `fixed`
- `per_unit`
- `per_finished_hour`
- `per_minute`
- `per_chapter`
- `per_actor`

Los servicios que deben escalar con el precio base pueden utilizar `percent_of_base`.

Los servicios por cantidad pueden usar `per_unit`, `per_chapter`, `per_actor`, etc.

## 7. Fórmula base

Duración estimada:

`durationMinutes = wordCount / wordsPerMinute`

Horas de audio:

`audioHours = durationMinutes / 60`

Precio base:

`basePrice = max(minimumBasePriceUsd, audioHours × basePfhRateUsd)`

## 8. Servicios

Cada selección genera una línea de cálculo.

Ejemplos:

`percent_of_base`

`basePrice × priceValue × quantity`

`fixed`

`priceValue × quantity`

`per_finished_hour`

`priceValue × audioHours × quantity`

`per_minute`

`priceValue × durationMinutes × quantity`

`per_chapter`

`priceValue × chapterCount × quantity`

`per_actor`

`basePrice × priceValue × quantity`

Los servicios marcados como `included` no generan un cargo adicional.

## 9. Complejidad

La complejidad global modula el esfuerzo y el precio final.

Valores iniciales:

- Standard: 1.00
- Medium: 1.05
- High: 1.12
- Cinematic: 1.20

Estos valores son configurables.

## 10. Protección contra precios excesivos

El sistema aplica un techo global:

`recommendedPrice <= basePrice × maxTotalPriceMultiplier`

Valor inicial:

`maxTotalPriceMultiplier = 1.85`

La finalidad es impedir que la combinación de muchos servicios produzca automáticamente una cotización desproporcionada.

## 11. Ajuste comercial

El motor permite un ajuste comercial posterior al cálculo.

Inicialmente se recomienda un rango configurable de:

-20% a +20%.

El resultado se separa en:

- precio calculado;
- ajuste comercial;
- precio final.

El Admin mantiene la decisión comercial.

## 12. Tiempo de producción

Se estima un tiempo interno utilizando:

`baseWorkMinutes = audioHours × baseWorkHoursPerAudioHour × 60`

más el tiempo de servicios seleccionados.

Después se aplica el factor de complejidad.

Este tiempo es una herramienta interna de planificación y no debe tratarse automáticamente como una promesa contractual al autor.

## 13. Congelación de propuesta

Cuando se cree una Propuesta, la propuesta debe conservar una fotografía de las reglas utilizadas:

- versión del modelo;
- servicios seleccionados;
- cantidades;
- valores aplicados;
- tiempo calculado;
- multiplicador de complejidad;
- precio base;
- ajuste comercial;
- precio final;
- plazo;
- revisiones;
- formatos;
- condiciones.

Si el catálogo cambia posteriormente, una propuesta existente no debe recalcularse automáticamente.

## 14. Relación con Project

Cuando el autor acepta una Propuesta:

`Proposal accepted → Project`

El Proyecto debe heredar los parámetros contratados desde la Propuesta aceptada.

Ejemplo:

- Propuesta: 4 revisiones.
- Proyecto: 4 revisiones contratadas.
- Producción: revisiones usadas 0/4.

No debe utilizarse un valor fijo legacy como `maxRevisions = 3`.

## 15. Separación de responsabilidades

### Catálogo global

Controla reglas para nuevas propuestas.

### Propuesta

Congela las condiciones comerciales acordadas.

### Proyecto

Representa lo contratado.

### Producción

Representa lo realizado.

## 16. Regla de negocio principal

El motor de precios es una herramienta de decisión interna.

Nunca debe impedir que el Admin haga un ajuste comercial razonable.

Nunca debe modificar una propuesta aceptada.

Nunca debe cambiar retroactivamente el precio de un proyecto contratado.
